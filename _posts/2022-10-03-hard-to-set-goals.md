# # 32 幹有些目標就很難定啊

延續前兩天關於「目標」的話題，今天突然想到一個可以寫寫看的主題，那就是在某些情況下「目標」是很難「設定」的。

有個說法是，離開校園、進到職場之後，許多實務上的「問題」是不好定義的、「目標」是模糊有彈性的。

先隨便舉個例，例如光是評估一個員工的「表現 / 績效」這件事，其實就滿難的（還發展出了各種評估工具）。

或是公司要如何衡量工程師的生產力？不太可能以 code 寫了幾行來衡量吧？有一說法是，愈強的工程師愈可以把 code  寫得簡潔優雅（但也不一定）。

這也讓有些很會讀書考試的人進了職場，一時難以適應。相反地，也有些學業表現普通的人，到了職場卻一鳴驚人、如魚得水。

\-

有個形容詞叫「well-defined」，常用來描述一個問題是否被「清楚定義」。

考試題目相對是 well-defined 的，但職場上很多問題卻不是 well-defined 的。

有可能解決問題前，還需要先搞清楚問題；也有可能問題解決到一半，還得回頭修正問題。

於是有些學校也開始倡導「Project-Based Learning」（專案導向學習），簡稱 PBL，希望透過專案式的學習，能彌補傳統教育的一些缺點（我沒深入了解 PBL ，這只是我個人看法）。

\-

有點扯遠了，回到我個人經驗的話，想列出一些我腦中覺得「很難設定目標」的事，例如：

\- 如何安排週末兩天空閒的時間、讓我爽度最大化？（要先定義爽度？）

\- 如何分配每個月金錢的使用？（牽涉到個人金錢價值觀、當下需求、具備的知識）

\- 如何找到適合的另一半？（對在一起的定義為何？何謂適合？而且對方還要剛好喜歡自己？）

\- 如何決定自己要投入的職涯發展方向？（千千萬萬迷惘年輕人包含我在內的難題？）

\- 如何知道自己的能力值得多少薪資？（牽涉到景氣、產業、職種...；還要面試面面看才知道）

\-

相對於以上關於人生、關於生活的各種尚未被「well-defined」的問題，我覺得寫程式好像單純一點 XD。

有時覺得寫程式的感覺，就像每天坐下來、然後開始「解題」一樣。反正終點就是要把東西搞到能動、可以 work、沒有 bug；解決手法不管，幹出來就對了。

在此就覺得負責規劃產品的人（PM？）很厲害，問題他們去定義、產品規格/使用者動線他們去規劃，我就是做出來就對了，有時這樣其實滿療癒的 R（是對人生多疲累 XD）。

（有可能我還太菜啦，工程師大神們應該不只是單純在解題而已）

\-

前麥肯錫顧問李聖珉（現在在台大教書）有開一個 FB 社團「培養解決問題的能力 CTPS」，我從中學到滿多的（推薦大家加入）。

在討論「解決問題」這件事時，他把問題分為「熟悉問題」與「陌生問題」。

他說，「熟悉問題」需要的是專家、是 SOP；而「陌生問題」則沒有可靠穩定的解法，需要批判性思維與科學方法。

我想他說的「陌生問題」，應該就是所謂尚未被「well-defined」的問題吧？

\-

可惜好像大多人生問題、人性問題都是陌生問題，我 follow 的另位大大彭明輝教授說，人生就像摸著石頭過河。

我只想對自己說：模糊是常態、不確定性是家常便飯；迷惘不會消失，試試與迷惘共舞。

學會駕駛自己這條小船，在沒有 GPS 絕對定位的情況下，嗅聞天候、親手掌舵，自我導航在遼闊的大海上。

（希望我能愈來愈認識世界，愈來愈認識自己）
